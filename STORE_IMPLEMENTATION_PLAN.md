# Подробный план реализации командного онлайн-магазина

## Цель и выбранный стек

Проект — небольшой фронтенд-магазин на **TypeScript + Vite + Vitest**. Список товаров загружается из **DummyJSON Products API**. Корзина, её состояние и расчёт суммы реализуются в браузере. Сервер, база данных, регистрация и оплата для задания не требуются.

DummyJSON подходит как источник демонстрационного каталога. Список товаров возвращается объектом с полями `products`, `total`, `skip` и `limit`. У товара есть поля вроде `id`, `title`, `description`, `category`, `price`, `thumbnail` и `images`. API также предоставляет поиск, категории, сортировку и постраничную загрузку. Запросы на добавление, изменение и удаление товара только имитируют операцию и не сохраняют изменения на сервере, поэтому для магазина используем API для чтения каталога, а не для хранения корзины.

Документация API: [DummyJSON Products](https://dummyjson.com/docs/products).

## Что обязательно для задания

- Стартовая страница «О нас», открывающаяся при загрузке приложения.
- Описание приложения, имена или GitHub-логины обоих участников и краткий вклад каждого.
- Работающий список товаров.
- Добавление и удаление товара в корзине.
- Отображение общей стоимости корзины.
- Хотя бы одна функция с понятным результатом и unit-тестами.
- Общий репозиторий, работа через ветки и Pull Request, взаимное ревью.
- Доска задач с назначенными ответственными и статусами.
- Публикация приложения по ссылке.
- Отдельная запись интервью и отдельный PR сдачи от каждого участника.

Поиск, фильтры, сортировка, промокод и сохранение корзины в `localStorage` — полезные расширения из примера гайда, но не обязательная часть минимальной версии.

## Этап 4. Согласовать структуру приложения и типы

Пример структуры, которую можно адаптировать под Vanilla TypeScript:

```text
team-store-app/
  src/
    api/
      productsApi.ts       # запросы к DummyJSON
    types/
      product.ts           # типы API и используемой модели товара
      cart.ts              # тип строки корзины
    utils/
      cart.ts              # операции корзины и расчёт суммы
    views/                 # рендер страниц/разделов, если решите разделить
    main.ts                # инициализация приложения
    style.css
  tests/
    cart.test.ts
  index.html
  package.json
  package-lock.json
```

1. Опишите ответ API минимальными используемыми полями: `products`, `total`, `skip`, `limit`.
2. Опишите товар: `id`, `title`, `category`, `price`, `description`, `thumbnail` или `images`.
3. Опишите строку корзины как `productId` и `quantity`.
4. Не используйте `any`; не копируйте все поля API, если интерфейс их не использует.
5. Для состояния загрузки и ошибки выберите явные типы или статусы.

**Результат этапа:** один общий набор типов используется API-функцией, каталогом и корзиной.

## Этап 6. Загрузить товары из DummyJSON

Для первой версии можно загрузить 12 записей запросом:

```text
https://dummyjson.com/products?limit=12
```

1. Вынесите сетевой запрос в функцию `getProducts()` в `src/api/productsApi.ts`.
2. Используйте `fetch` и проверяйте `response.ok` до чтения успешных данных.
3. Преобразуйте ответ к типу API.
4. Верните из функции массив `products` (и `total`, если нужна пагинация).
5. Не заставляйте компонент карточки самостоятельно ходить в API.
6. В интерфейсе предусмотрите состояние загрузки.
7. При ошибке сети или HTTP покажите понятное сообщение и кнопку повторной загрузки, если успеваете.
8. Для пустого массива покажите отдельное сообщение.
9. Не добавляйте корзину в API: DummyJSON не хранит её изменения надолго.

**Результат этапа:** каталог загружается из API, а загрузка, пустой ответ и сбой сети отображаются понятным образом.

## Этап 7. Отобразить каталог и карточки

1. Отобразите массив полученных товаров.
2. Для каждого товара покажите название (`title`), категорию, цену и кнопку «В корзину».
3. Покажите `thumbnail` или подходящее изображение из `images`.
4. Для изображений укажите осмысленный `alt`; предусмотрите вариант, если картинка не загрузилась.
5. Можно дополнительно показать описание, но не перегружайте карточку.
6. Используйте `id` API как идентификатор и ключ для отображения.
7. Проверьте каталог при обычной загрузке и на узком экране.

**Результат этапа:** посетитель видит карточки и может добавить конкретный товар из его карточки.

## Этап 8. Реализовать состояние и операции корзины

1. Создайте состояние корзины в памяти приложения.
2. В строке корзины храните `productId` и `quantity`; данные товара получайте из каталога по `productId`.
3. При первом добавлении товара создайте строку с количеством `1`.
4. При повторном добавлении найдите строку по `productId` и увеличьте `quantity`; не создавайте дубликат строки.
5. В корзине найдите соответствующий товар в загруженном каталоге.
6. Отобразите название, цену за единицу, количество и стоимость строки (`price × quantity`).
7. Добавьте кнопку удаления строки.
8. Для пустой корзины покажите сообщение и итог `0`.
9. Не разрешайте некорректные количества, если позже добавите кнопки изменения количества.

**Результат этапа:** добавление, повторное добавление и удаление работают, строки не дублируются.

## Этап 9. Реализовать и протестировать расчёт суммы

1. Вынесите расчёт корзины в чистую функцию, например `calculateCartTotal`.
2. Передавайте ей минимальные данные, необходимые для расчёта.
3. Считайте сумму как сумму произведений цены на количество.
4. Покройте тестами:
   - пустую корзину (ожидаем `0`);
   - один товар с количеством больше одного;
   - несколько товаров с разными ценами и количествами.
5. Если добавление/объединение строк вынесено в чистую функцию, проверьте и повторное добавление одного ID.
6. Запустите `npm test` и убедитесь, что Vitest показывает найденные тесты и их результат.
7. Оставьте эту функцию понятной для демонстрации на интервью.

**Результат этапа:** сумма проверяется unit-тестами без запуска браузера и DOM.

## Этап 10. Добавить расширения после минимальной версии

Дополнительные возможности реализуйте только после проверки основного сценария.

1. **Количество:** кнопки `+` и `−`, нижний предел `1`.
2. **Поиск:** поле поиска по названию без учёта регистра.
3. **Категория:** список категорий из `/products/category-list` или `/products/categories`, вариант «Все категории».
4. **Цена:** диапазон с включительными границами.
5. **Сортировка:** исходный порядок, цена по возрастанию, цена по убыванию.
6. **Совместная фильтрация:** поиск, категория и цена применяются одновременно; сортировка — к уже отфильтрованному списку.
7. **Пустая выдача и сброс:** сообщайте, когда товаров нет, и сбрасывайте поля к исходным значениям.
8. **`localStorage` (по желанию):** сохраняйте корзину после перезагрузки, проверьте некорректное/отсутствующее сохранённое значение.
9. **Промокод (по желанию):** согласуйте правила скидки, не накапливайте скидку при повторном вводе.

Фильтрацию можно выполнять над уже загруженными данными в браузере. Если используете API для запроса категорий, поиска и сортировки, учитывайте параметры и формат ответа из документации DummyJSON.

**Результат этапа:** дополнительные функции работают вместе, не нарушая каталог и корзину.
